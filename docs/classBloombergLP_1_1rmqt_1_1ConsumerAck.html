◆ Type

enum BloombergLP::rmqt::ConsumerAck::Type

How a consumer resolved a delivery.

Each value names the AMQP method it sends and the value of that method's requeue flag. Only basic.reject counts the delivery as a failed attempt; basic.nack does not.

Values are fixed and must not be renumbered.

See also
https://www.rabbitmq.com/docs/nack
https://www.rabbitmq.com/docs/quorum-queues#when-is-delivery-count-incremented

◆ supportsMultiple()

bool BloombergLP::rmqt::ConsumerAck::supportsMultiple ( Type  type)
static

RETURN true if the AMQP method that type sends carries a multiple flag, and so may resolve every unresolved delivery up to and including its delivery tag in one frame.

basic.ack and basic.nack carry it, basic.reject does not, so a reject is always sent one frame per delivery. Combining rejects would resolve only the highest delivery tag and leave the rest outstanding.

See also
https://www.rabbitmq.com/amqp-0-9-1-reference#basic.reject
